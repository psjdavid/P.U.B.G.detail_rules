## 3. 참가 신청 및 팀 구성
### 3.1 참가 방식
참가자는 아래 두 방식 중 하나로 신청할 수 있습니다.
1. 팀 참가
  1. 사전에 팀을 구성한 뒤 대표자가 신청합니다.
  2. 모든 팀원의 이름, 소속, 역할, 연락처를 함께 제출해야 합니다.
2. 개인 참가
  1. 개인으로 신청한 뒤 팀 빌딩 세션을 통해 팀을 구성합니다.
  2. 게임 개발 경험이 없더라고 기획, 아트, UI/UX, 사운드, 문서화, QA등 다양한 역할로 참여할 수 있습니다.
### 3.2 팀 구성 원칙
1. 팀 인원은 최소 `1`명, 최대 `5`명입니다.
2. 한 사람은 하나의 팀에만 참여할 수 있습니다.
3. 팀 구성은 원칙적으로 개발 시작 전까지 확정해야 합니다.
4. 개발 시작 이후 팀원 추가·교체는 운영진의 사전 승인이 있는 경우에만 가능합니다.
5. 팀원 간 역할 분담은 자유이나, 제출물과 발표에서 각 팀원의 기여 내용을 간략히 명시해야 합니다.
6. 개인 참가자는 팀 빌딩 과정에서 희망 역할, 사용 가능 도구, 경험 수준 등을 기준으로 팀 매칭을 지원받을 수 있습니다.

## 4. 대회 주제
### 4.1 공식 주제
대회의 공식 주제는 **개발 시작 시각에 공개**됩니다.
1. 주제는 게임의 장르, 세계관, 핵심 시스템, 플레이 경험 등 다양한 방식으로 해석할 수 있습니다.
2. 주제를 반드시 문자 그대로 해석할 필요는 없습니다.
3. 단, 제출물과 발표를 통해 팀이 주제를 어떻게 해석했는지 확인할 수 있어야 합니다.
4. 운영진은 필요 시 주제와 함께 보조 키워드, 예시, 유의 사항을 안내할 수 있습니다.
```text
[예시]
공식 주제: "연결"
보조 키워드: 협력 / 단절 / 신호 / 반복
```
### 4.2 주제 적합성
단순히 제목이나 배경에만 주제를 넣기보다, 다음 요소에 자연스럽게 반영하는 것을 권장합니다.

1. 게임의 핵심 규칙과 플레이 방식
2. 플레이어의 목표와 선택
3. 게임 세계관 및 스토리
4. 시각·사운드·연출
5. 협동 또는 경쟁 구조
6. 반복 플레이의 동기

## 5. 개발 규정
### 5.1 개발 시작 기준
1. 대회 주제 공개 및 개발 시작 시각 이후부터 본격적인 게임 제작을 시작해야 합니다.
2. 대회 이전에 게임의 핵심 로직, 스테이지, 캐릭터, 레벨, 게임플레이 시스템을 미리 제작하는 행위는 금지합니다.
3. 다만 공정한 개발 환경을 위해 아래 항목은 사전 준비를 허용합니다.
### 5.2 사전 준비 허용 범위
다음 항목은 대회 전 준비하거나 보유한 자료를 사용할 수 있습니다.
1. 개발 엔진 설치 및 기본 환경 설정
2. IDE, VCS, 협업 도구 설정
3. 팀원 간 역할 분담 및 개발 계획 수립
4. 직접 제작했거나 적법한 라이선스를 보유한 범용 에셋
5. 폰트, 무료 아이콘, 범용 UI 프레임워크
6. 공개 라이브러리, 오픈소스 패키지, 게임 엔진 공식 플러그인
7. 대회 전부터 보유한 포트폴리오용 범용 코드 중 게임의 핵심 재미와 직접 관련 없는 부분
  (예: 저장 시스템, 기본 이동 템플릿, 설정 창, 사운드 매니저 등)

단 사전 준비물 사용 여부와 출처는 제출 문서에 반드시 기재해야 합니다.

### 5.3 사전 제작 금지 범위
다음 항목은 대회 시작 전 제작하거나 완성된 형태로 준비할 수 없습니다.
1. 이번 대회 주제에 맞춘 게임 기획서
2. 핵심 게임 루프 및 주요 플레이 시스템
3. 이번 대회용으로 제작한 스테이지·퀘스트·퍼즐·보스 패턴
4. 이번 대회 결과물의 핵심 캐릭터·배경·스토리·연출
5. 기존에 제작하던 게임을 일부 수정하여 제출하는 행위
6. 다른 공모전·게임잼·수업 프로젝트 결과물을 재활용하는 행위

운영진은 공정성 문제가 있다고 판단되는 경우, 개발 기록·커밋 내역·작업 파일·원본 출처 등에 대한 추가 확인을 요청할 수 있습니다.

## 6. 에셋, 외부 코드 및 생성형 AI 사용 규정
### 6.1 기본 원칙
외부 에셋, 코드, 라이브러리, 생성형 AI 도구 사용은 원칙적으로 허용합니다.
다만 모든 팀은 사용한 자료의 **출처, 라이선스, 사용 범위**를 명확히 기록해야 합니다.

사용 허가 여부와 별개로, 타인의 결과물을 본인 또는 팀의 창작물인 것처럼 제출하는 행위는 금지됩니다.

### 6.2 외부 에셋
다음과 같은 자료를 사용할 수 있습니다.
1. 무료·유료 에셋 스토어 자료
2. 저작권자가 사용을 허용한 이미지, 3D 모델, 폰트, 음원, 효과음
3. Creative Commons 또는 이에 준하는 라이선스 자료
4. 팀원이 직접 제작한 기존 범용 에셋
5. 대회 중 직접 제작한 에셋

단, 아래 사항을 준수해야 합니다.
1. 상업적 이용 가능 여부와 저작자 표기 조건을 확인해야 합니다.
2. 사용한 자료의 출처 링크 또는 라이선스 정보를 제출 문서에 기재해야 합니다.
3. 타인의 게임 리소스, 캐릭터, 로고, BGM, UI를 무단으로 사용해서는 안 됩니다.
4. 저작권 분쟁 소지가 있는 자료를 사용한 경우 해당 팀은 심사 제외 또는 실격될 수 있습니다.

### 6.3 외부 코드 및 오픈소스
1. 공개 라이브러리, 엔진 공식 패키지, 오픈소스 코드는 사용할 수 있습니다.
2. 사용한 라이브러리·패키지·코드의 이름, 출처, 라이선스를 명시해야 합니다.
3. 인터넷에서 찾은 코드를 그대로 사용한 경우에도 출처를 반드시 기재해야 합니다.
4. 다른 팀의 코드, 비공개 프로젝트 코드, 유료 강의·교재의 결과물을 무단 복제하는 행위는 금지됩니다.

### 6.4 생성형 AI 도구
생성형 AI 도구는 아이디어 정리, 코드 보조, 이미지·사운드 초안 제작, 문서 작성 보조 등에 사용할 수 있습니다.
단, 다음 원칙을 지켜야 합니다.
1. 사용한 도구와 사용 목적을 제출 문서에 기재합니다.
2. AI 생성 결과물이라도 저작권·라이선스 문제는 참가 팀의 책임입니다.
3. 특정 작가·스튜디오·게임의 화풍이나 결과물을 무단 모방하도록 유도한 자료는 사용을 지양합니다.
4. AI가 생성한 코드나 에셋을 사용했더라도, 팀은 해당 결과물의 작동·수정·책임을 부담해야 합니다.
5. AI 사용 여부 자체는 감점 사유가 아니지만, 팀의 기획 의도와 구현 기여가 분명해야 합니다.

예시:
```markdown
## 외부 자료 및 AI 사용 내역

- Unity Input System: Unity 공식 패키지
- 무료 효과음: Freesound, CC0 라이선스
- 폰트: [폰트명], OFL 라이선스
- 생성형 AI: 게임 내 NPC 대사 초안 정리에 사용
- 생성형 AI 이미지: 사용하지 않음
```

## 7. 제출물 안내
모든 팀은 마감 시각 전까지 아래 항목을 제출해야 합니다.
마감 이후 제출은 원칙적으로 인정되지 않으며, 서버 오류 등 불가피한 사유가 있는 경우 즉시 운영진에게 연락해야 합니다.

### 7.1 필수 제출물
|제출물|설명|
|:--|:------|
|게임 빌드 또는 실행 링크|심사위원과 참가자가 실제로 플레이할 수 있는 형태|
|소스 코드 Repository|GitHub, GitLab 등 접근 가능한 저장소|
|프로젝트 README|게임 설명, 조작법, 설치·실행 방법, 출처 표기|
|발표 자료|PPT, PDF, Canva 링크 등 [3~5]분 발표용 자료|
|게임 플레이 영상|	[30초~2분] 내외의 짧은 시연 영상 또는 GIF|
|팀원 및 역할표|팀원별 담당 역할과 기여 내용|
|외부 자료 사용 내역|에셋·폰트·음원·라이브러리·AI 도구 등 출처|
|알려진 이슈 목록|남아 있는 버그, 미구현 기능, 실행 유의 사항|

### 7.2 권장 빌드 형식
가능한 한 심사 환경에서 쉽게 실행할 수 있는 형식을 권장합니다.

1. WebGL / 웹 빌드: itch.io, GitHub Pages 등
2. Windows: .zip 압축 파일 또는 실행 파일
3. Android: .apk
4. macOS: 별도 안내가 있는 경우에 한함
5. 모바일·VR·특수 장비 기반 게임: 사전에 운영진과 심사 환경을 반드시 협의해야 함

### 7.3 Repository 공개 원칙
1. 제출 Repository는 원칙적으로 공개(Public) 또는 심사위원 접근이 가능한 비공개(Private) Repository여야 합니다.
2. 커밋 기록을 유지하는 것을 권장합니다.
3. 대회 종료 후, 팀의 선택에 따라 소스 코드 공개 범위는 조정할 수 있습니다.
4. 단, 심사 종료 전까지 운영진과 심사위원이 확인할 수 있어야 합니다.
5. 비공개 Repository 사용 시 운영진 계정 또는 지정 계정에 접근 권한을 부여해야 합니다.

## 8. 심사 기준
심사위원은 팀이 구현한 핵심 재미, 창의적 해석, 플레이 가능성, 완성도를 종합적으로 평가합니다.

### 8.1 배점
|평가 항목|	배점|	평가 기준|
|:----|:-----|:-------|
|게임성·재미|	30점|	플레이가 재미있는가, 핵심 루프가 명확한가, 다시 플레이하고 싶은가|
|주제 적합성·창의성|	20점|	주제를 독창적으로 해석했는가, 주제와 플레이 경험이 유기적으로 연결되는가|
|핵심 메커니즘 완성도|	20점|	핵심 시스템이 안정적으로 작동하는가, 게임의 목표와 규칙이 분명한가|
|기획·UX·밸런싱|	15점|	조작·UI·난이도·피드백이 직관적인가, 플레이어가 자연스럽게 게임을 이해하는가|
|발표·개발 과정|	10점|	개발 의도와 과정이 설득력 있게 전달되는가, 팀 협업과 문제 해결 과정이 드러나는가|

## 9. 발표 및 시연
### 9.1 발표 구성
각 팀은 [3]분 발표와 [2]분 질의응답을 진행합니다.
이후 심사위원은 [3~5]분 동안 게임을 직접 플레이합니다.
발표에는 다음 내용을 포함하는 것을 권장합니다.

1. 팀명 및 팀원 소개
2. 게임의 한 줄 소개
3. 공식 주제 해석
4. 핵심 게임 메커니즘
5. 가장 공들인 부분 또는 해결한 문제
6. 실제 플레이 시연
7. 향후 개선하고 싶은 점

### 9.2 발표 유의 사항
1. 발표 시간은 엄수해야 합니다.
2. 게임 실행 오류에 대비하여 플레이 영상 또는 GIF를 준비하는 것을 권장합니다.
3. 발표 자료의 형식은 자유입니다.
4. 게임 설명보다 실제 플레이 경험이 잘 전달되도록 구성하는 것을 권장합니다.
5. 현장 상황에 따라 발표 순서는 운영진이 조정할 수 있습니다.

## 11. 금지 행위 및 실격 기준
아래 행위가 확인될 경우 운영진 판단에 따라 경고, 감점, 심사 제외 또는 실격 처리될 수 있습니다.

### 11.1 저작권 및 표절
1. 타인의 게임, 소스 코드, 에셋, 음악, 캐릭터, 로고 등을 무단으로 사용한 경우
2. 기존 게임 또는 타 팀의 결과물을 실질적으로 복제한 경우
3. 외부 자료 사용 사실 또는 출처를 고의로 숨긴 경우
4. 라이선스 조건을 위반한 자료를 사용한 경우

### 11.2 부정 참여
1. 대회 시작 전 핵심 결과물을 제작한 경우
2. 참가 등록자 외 인원이 실질적인 개발에 참여한 경우
3. 다른 팀의 개발을 방해하거나 결과물을 훼손한 경우
4. 허위 정보 또는 타인의 신분을 이용하여 참가한 경우

### 11.3 부적절한 콘텐츠
1. 혐오, 차별, 폭력, 성적 대상화, 불법 행위 조장 등 타인에게 불쾌감 또는 피해를 줄 수 있는 콘텐츠
2. 특정 개인·집단·기관을 비방하거나 명예를 훼손할 수 있는 콘텐츠
3. 행사 성격 및 학교 공동체의 기준에 부합하지 않는 콘텐츠

게임 표현의 자유를 존중하되, 운영진은 행사 환경과 공개 범위를 고려하여 시연·공개를 제한할 수 있습니다.

## 12. 운영 및 안전 수칙
### 12.1 공용 공간 이용
오프라인으로 진행되는 경우 모든 참가자는 대회 장소의 이용 수칙을 준수해야 합니다.

1. 시설물과 장비를 훼손하지 않습니다.
2. 다른 팀의 개발과 발표를 방해하지 않습니다.
3. 지정된 장소 외에서의 소음·취식·흡연 등은 금지될 수 있습니다.
4. 귀중품은 각자 보관하며, 분실물에 유의합니다.
5. 비상 상황 발생 시 운영진의 안내에 따릅니다.

### 12.2 건강한 개발 문화
P.U.B.G.는 밤샘이나 과로를 경쟁 요소로 장려하지 않습니다.

1. 충분한 휴식과 식사를 권장합니다.
2. 팀원 간 무리한 업무 배분, 폭언, 배제, 강요를 금지합니다.
3. 협업 과정에서 갈등이 발생한 경우 운영진에게 도움을 요청할 수 있습니다.
4. 팀원 모두가 안전하고 존중받는 환경에서 참여할 수 있도록 협조해 주세요.

## 14. 자주 묻는 질문

#### Q1. 게임 개발 경험이 없어도 참가할 수 있나요?
네. P.U.B.G.는 프로그래머뿐 아니라 기획, 아트, UI/UX, 사운드, QA, 발표 등 다양한 역할의 참가를 환영합니다. 개인 참가자의 경우 팀 빌딩을 지원합니다.

#### Q2. 혼자 참가해도 되나요?
네. 개인 참가가 가능하며, 팀 빌딩 세션을 통해 다른 참가자와 팀을 구성할 수 있습니다. 개인 개발로 완주하는 것도 가능합니다.

#### Q3. 대회 전에 만든 코드나 에셋을 사용해도 되나요?
범용 시스템, 적법한 외부 에셋, 일반 라이브러리 등은 사용할 수 있습니다. 단, 이번 대회 결과물의 핵심 게임플레이나 주제에 맞춰 사전 제작한 내용은 사용할 수 없습니다. 사용한 자료는 반드시 출처와 사용 내역을 기재해야 합니다.

#### Q4. 생성형 AI를 사용해도 되나요?
네. 사용할 수 있습니다. 다만 사용한 도구와 사용 목적을 제출 문서에 기재해야 하며, 결과물의 저작권·라이선스 문제에 대한 책임은 참가 팀에 있습니다.

#### Q5. 게임을 완성하지 못하면 탈락인가요?
아닙니다. 다만 심사위원이 플레이할 수 있는 최소한의 빌드 또는 시연 영상은 제출해야 합니다. 완성도보다 핵심 아이디어와 플레이 경험을 명확히 보여주는 것이 중요합니다.

#### Q6. 어떤 게임 엔진을 사용해야 하나요?
Unity, Unreal Engine, Godot, RPG Maker, Ren'Py, 웹 기술, 자체 엔진 등 제한 없이 사용할 수 있습니다. 단, 심사 환경에서 실행 가능한 형태로 제출해야 합니다.

#### Q7. 모바일 게임이나 VR 게임도 가능한가요?
가능합니다. 다만 별도 기기나 특수 장비가 필요한 경우 심사 환경을 사전에 운영진과 협의해야 합니다. 일반 PC에서 시연이 어려운 경우 플레이 영상도 함께 제출하세요.

#### Q8. 개발 중 도움이 필요하면 어떻게 하나요?
기술적 문제, 팀 내 협업 문제, 제출 문제 등이 생기면 Instagram(@cnu_crafton)을 통해 운영진에게 문의할 수 있습니다.
